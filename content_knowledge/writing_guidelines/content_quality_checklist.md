# Content quality checklist

Used by Skill E (QA) and Skill G (pre-publication review). Passing this checklist is **not** human approval and **not** a guarantee of factual correctness beyond the deterministic rules encoded in `core.writing.compliance`.

## Hard failures (must revise)

- [ ] Partner tier correct (Diamond, never Premier)
- [ ] No banned terminology / competitor clouds / retired names
- [ ] No em/en dashes (AI-Native hyphen exception only)
- [ ] No unsupported numerical or customer claims (relative to brief + proof excerpts supplied)
- [ ] No invented social proof / logistics
- [ ] Sentence case on titles/subjects/CTAs when those fields are present
- [ ] Channel hard limits (email subject <40, Google/LinkedIn ad lengths, etc.)
- [ ] At most one credential pattern; no pure standalone brag line when detected
- [ ] Facts preserved on rewrite (optimization must not invent new numbers)

## Soft warnings

- [ ] Possible mechanical triad / abstraction phrasing
- [ ] Multiple credential mentions
- [ ] Recap-bridge language
- [ ] CEO-voice vs v17 wording conflict on leadership assets
- [ ] Social limits unknown (no approved template in brief)

## Pre-publication (Skill G)

1. Run writing compliance + existing brand/hard-constraint/originality QA.
2. Resolve hard failures via optimize/refine.
3. Present to human approval gate.
4. Export only after explicit human approval.
